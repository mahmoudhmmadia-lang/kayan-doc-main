\label{ch:builder-dashboards}

\section{What will you build in this chapter?}
\label{sec:builder-dashboards-intro}

Once records accumulate, managers need figures that summarize the work, such as the number of open or overdue requests. This chapter explains building a dashboard from start to viewing: you create it in the list, add sections and widgets and link each widget to its data source, set its settings and filters, then preview and publish it. It then explains how the team views and exports it, how AI dashboards are published as pages in apps, and how to ask quick questions in AI Reports.

Each viewer sees in a dashboard what their permissions allow, unless its owner explicitly chooses otherwise, which is why reviewing the access level before publishing recurs across the pages.

\begin{rcnote}[Example: Horizon]
Horizon's system administrator builds a “Visits follow-up” dashboard showing visit requests in each status and each branch, then publishes it in the “Branch services” app, so every morning Sarah Al-Khatib reviews the requests waiting for her decision.
\end{rcnote}
