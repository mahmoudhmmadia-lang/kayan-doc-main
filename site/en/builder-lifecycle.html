Status fields and lifecycle rules

1.9

Status fields and lifecycle rules

A “Status” field follows the work stages of a status template, such as “New”, then “Under review”, then “Approved”. “Lifecycle rules” add controls to it: when a move from one status to another is allowed, who may not make it, which fields are set automatically during the move, and whether the record is locked in a given status. So following the procedure does not depend on employees remembering it.

Where and who: Builder workspace → “Fields” → choose the status field → “Lifecycle rules”. The rules need a “Fixed template” in the field's settings and are not available on built-in record types. Status templates themselves are explained in the Tasks chapter, on page 4.12.

Example: Horizon

The administrator forbids the requester from moving a “Visit requests” record to “Approved”, so Omar Haddad cannot approve his own request. They add an effect that writes the approval date and approver, then lock the approved request so its data does not change after Sarah Al-Khatib approves it.

Status changes only through transitions

When “Status changes only through transitions” is on, forms, imports and automations cannot set the status directly, and every new record starts at the first status. If an automation changes the status, review it before turning this option on.

Steps and check

  1. 1
    Open the status field in “Fields”, and in “Type settings” choose “Fixed template” and the suitable status template.
  2. 2
    Open “Lifecycle rules”, choose the transition to set, add its condition in “Only when” and its message in “Message when blocked”.
  3. 3
    In “Can't be done by members in”, choose the requester field if requesters may not approve their own request.
  4. 4
    In “When the transition runs”, add an effect that writes the date or the current member, then set editing lock for the final status.
  5. 5
    Publish the changes and try the transition with a test record, once with the condition missing and once with it met.

Check and recovery: the transition should be blocked with your message when the condition is missing, and go through and write the chosen fields when it is met. If “Lifecycle rules” do not appear, choose “Fixed template” first; if the type is built into the system, these rules are not available for it.
